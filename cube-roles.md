# Roles for the 14 empty cells

27 cells = 9 operators x 3 grains. Pharos and the `network/1` pack already use 13 (listed at the end). This file proposes a role for each of the other 14, using the coordinates in pharos `cells.json` (mode, domain, terrain, stance) and what the downloaded sources describe.
These are **nominations** (my reading), not results. They should be added to the blind-agreement test as a further set of moves before anyone relies on them.
Addresses are byte ranges into the plain-text copy of each source in `sources/`; items marked "via summary" or "not downloaded" have no address because I did not read the source text myself.

## What the pattern says

- **Grain column.** Ground cells are about spaces and rules (create a space, link spaces, join spaces, clear a field). Figure cells are about one entry (attend, merge, re-key). Pattern cells are about groups and networks (compose a group, unravel a tree, trace the graph, re-key a group).
- **The gaps are mostly bulk and group operations.** Four of the 14 are the group forms that Keyhive and Willow both care about: compose a group, unravel a delegation tree, trace the membership graph, re-key a group.
- **SIG is audit and retention.** All three SIG cells are attention, which is how access audit and space-driven eviction would be recorded if you want them.
- **SYN needs one correction.** EOQL resolves forks with SYN, so dispute settlement should move from REC·Ground to SYN·Figure when it merges heads.

## The 13 cells already used

NUL·Ground (frame); NUL·Figure (tombstone); NUL·Pattern (sealed region); INS·Figure (offer, gift copy); SEG·Figure (revoke, delete); CON·Figure (grant); DEF·Ground (capability rule, standpoint); DEF·Figure (kind); DEF·Pattern (holon); EVA·Ground (dispute); EVA·Figure (attest, receipt); EVA·Pattern (fold-hash agreement); REC·Ground (rule change).
